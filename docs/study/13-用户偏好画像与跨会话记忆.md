# 用户偏好画像:从行为信号到评分上下文

## 这个知识点是什么

跨会话记忆指系统把用户"过往的行为"(点开了什么、订阅了什么)提炼成一张**偏好画像**,在后续的自动化决策里作为上下文注入——越用越准。第一版的实现路径:点击行为 → 聚类键信号,其他主题的关键词 → 兴趣面信号,两者聚合成一张有限长度的偏好列表,塞进 Analyst 的评分 prompt。

类比:咖啡店店员记住了你常点的口味——你点单时他会说"今天要不要试试新的那款?和你平时喝的接近"。但他不会因此替你改菜单:你明确点的还是照做(主题判定标准优先),偏好只在"两杯都符合"时影响推荐。

## TradeWinds 为什么需要它

评分完全按主题判定标准执行时,用户只能靠"把描述写细"来表达口味;而用户在 Feed 里的点击已经在无声地表达偏好——这些信号不用就浪费了。扩展计划把跨会话记忆列为按产品价值排序的第一项,依赖标注得很清楚:items 评分历史 → 用户偏好画像。

## 本项目怎么实现的

三段式,信号从弱到强:

1. **行为采集**([models/engagement.py](../../src/tradewinds/models/engagement.py)):`item_clicks` 表(用户×条目唯一约束,天然幂等);前端 Feed 卡片点击时 fire-and-forget 上报 `POST /items/{id}/click`,归属隔离(别人的条目 404);
2. **画像聚合**([services/preference_service.py](../../src/tradewinds/services/preference_service.py)):`build_profile` 按权重聚合——点击条目的聚类键(强信号,排前)→ 同用户其他主题的关键词(弱信号),去重、限量 12 条;构建时排除当前主题,避免"用 B 主题的偏好影响 B 自己的评分"造成回音室;
3. **上下文注入**([agents/analyst.py](../../src/tradewinds/agents/analyst.py)):`build_scoring_prompt_section` 把画像渲染成独立段落追加到评分 prompt,并**显式写明"仅作参考信号,判定仍以本主题判定标准为准"**——这句约束是关键设计:记忆影响的是评分接近时的取舍与推荐理由的措辞,而不是劫持判定标准。

## 踩过的坑

1. **回音室风险**:最初把画像范围包含了当前主题自身的历史,结果评分依据里出现了"当前主题的旧条目偏好",越评越窄。改为 `exclude_topic_id` 排除当前主题后,画像只提供跨主题的增量信息;
2. **信号强弱要分层**:主题关键词人人都有(弱信号),点击是稀疏但昂贵的强信号——排序时点击聚类在前,关键词只取每个主题前 4 个,总量封顶 12 条防止 prompt 膨胀;
3. **集成测试断言 prompt 而非断言分数**:LLM 被打桩后分数是假的,真正要验证的是"画像确实进入了 prompt"——让 FakeRunner 捕获 prompt 文本,断言包含画像标记段落与点击产生的聚类键。
