# 异步并发抓取与速率控制

## 这个知识点是什么

异步并发抓取就是用一个线程(事件循环)同时向多个信息源发起 HTTP 请求,谁先返回先处理,而不是"发一个、干等、再发下一个"。速率控制则是在"并发"这匹马前面加缰绳:限制同时在途的请求数(信号量)和两次请求之间的最小间隔,避免把对方网站打疼。

类比:并发抓取像同时派 5 个快递员分头取件;速率控制规定每个小区每分钟只放行 1 趟——快,但不惹人报警。

## TradeWinds 为什么需要它

一次主题执行要同时访问 arXiv、Hacker News、GitHub 和任意网页。串行抓取会让管道耗时变成各源延迟之和(数秒到数十秒);不限速的并发又会被限流甚至封 IP(arXiv 明确要求礼貌抓取,GitHub 匿名搜索每小时仅 10 次)。所以"并发 + 限速"是一对必须同时出现的组合。

## 本项目怎么实现的

- **并发**:[agents/retriever.py](../../src/tradewinds/agents/retriever.py) 用 `asyncio.gather` 同时调用各源客户端,任何单一客户端都不会阻塞其他源;
- **限速**:[tools/base.py](../../src/tradewinds/tools/base.py) 的 `RateLimiter` 把 `asyncio.Semaphore`(最多 5 个在途请求)和"锁内计时 + 不足间隔就 sleep"(相邻请求至少隔 1 秒)组合起来,三个源客户端共享同一实例,在 `httpx.AsyncClient` 发请求前统一经过它;
- **客户端同构**:每个源只实现 `search(plan, *, topic_id, seen_hashes)`,查询拼装、时间窗过滤、指纹去重都在各自 `_parse` 里,协议见 `SourceClient`;
- **零网络测试**:契约测试用 `httpx.MockTransport` 回放录制固件(正常/空结果/畸形响应三份),既快又稳定,CI 不依赖外网。

## 踩过的坑

1. **asyncpg 连接绑定事件循环**:集成测试里用 `asyncio.run` 检查数据库时,不能复用应用 lifespan 里创建的 engine(它的连接属于另一个循环),必须另建一个 engine——报错形如 "attached to a different loop";
2. **`zip(a, b, strict=True)` 要求等长**:`zip(stamps, stamps[1:], strict=True)` 必然抛 ValueError,相邻差分应该用 `itertools.pairwise`;
3. **httpx MockTransport 与绝对 URL**:客户端直接用完整 URL 请求时,`MockTransport` 会拦截一切请求,不需要配 base_url;但测试里断言查询参数要用 `request.url.params` 而不是手拼字符串。
