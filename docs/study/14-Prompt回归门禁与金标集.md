# Prompt 回归门禁:金标集如何防 prompt 退化

## 这个知识点是什么

prompt 是 LLM 应用的"源代码",但它没有编译器、没有类型检查——改一句话,产物可能悄悄从"JSON 数组"变成"带解释的散文",从"聚类键一致"变成"各写各的"。prompt 回归门禁就是给 prompt 建立一套**离线可跑的评测集**:每次改 prompt(或换模型、改 schema),评测必须全绿才能合并。

类比:给 prompt 装上 CI——金标集是测试用例,"录制固件 + 业务期望断言"是断言方式,CI 必跑是门禁开关。

## TradeWinds 为什么需要它

Planner/Analyst/Editor 三个角色的 prompt 决定了整个管道的产物形状:检索计划、评分聚类、摘要。任何一次"顺手优化措辞"都可能让 Editor 忘记保留英文专有名词,或让 Analyst 的聚类键大小写漂移——下游全部静默受损。人工抽查不可持续,所以把验收标准写成金标集,让机器把关。

## 本项目怎么实现的

- **三角色金标集**([tests/agents/golden/](../../tests/agents/golden/)):planner 10 例、analyst 8 例、editor 6 例。每例含三部分:`输入`(描述/判定标准/条目)、`model_output`(录制自真实 LLM 的产物固件)、`expect`(业务要点);
- **断言业务要点,不逐字比对**:Planner 断言关键词覆盖与源选择;Analyst 断言分数区间(核心 ≥7、噪音 ≤3)、同事件聚类键一致、输入全覆盖;Editor 断言摘要保留核心实体、长度边界、**"内容没披露数字就不许出现编造数字"**——这条"反脑补"断言比相似度更有效地守住忠实性;
- **规模守卫**:断言各金标集最少条数(10/8/6),目录被清空时测试显式失败而非静默失去保护;
- **门禁语义**:三个金标测试套件随 CI 每次运行,不依赖网络(固件回放)——prompt 变更的 PR 必须让全部金标通过才能合并。引入真实 LLM 在线评测时,只需把回放 provider 换成真实 provider,断言不变。

## 踩过的坑

1. **断言写错数据源**:期望键存在 `expect` 里、被断言的值在 `item` 里,引用错对象会让断言自身 KeyError——先跑一遍红灯确认断言真的执行了(本迭代就踩了这一下,assert 用了不存在的 `expect["url"]`);
2. **期望与固件自相矛盾**:要求"命中 2 个候选词"却只给了 1 个候选词,金标集自己先红;写用例时要先跑断言再提交;
3. **"反脑补"断言要克制**:只对"原文确无数值"的用例断言无数字,否则正常改写数字的摘要会被误杀——断言范围必须与用例语义精确对齐。
